# 运行说明

## 仓库范围

公开仓库提供应用源码、依赖锁定、工作流模板和界面展示。原始业务文档、处理后的知识包、原生图谱抽取结果、索引、模型和容器镜像需单独准备。没有对应资料时，可以阅读代码并构建前端，不能直接启动完整知识问答或复现所有数据相关测试。

## 安装开发依赖

需要 Python 3.12 和 Node.js 22。PowerShell 进入仓库根目录后执行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
npm --prefix frontend ci
npm --prefix frontend run build
```

## 配置模型

安装 Ollama 后下载 `qwen3:8b`：

```powershell
ollama pull qwen3:8b
.\.venv\Scripts\python.exe scripts/configure.py
```

`configure.py` 创建本机私有 `.env`，不会覆盖已有配置。模型启用前保持关闭；完成实际中文、JSON 和工具调用验证后执行 `scripts/model_smoke.py --enable`。私有配置只保存在本机。

## 知识数据

应用启动会读取 `data/processed/knowledge.json`。资料处理实现位于 `backend/icp/ingest.py`，按本项目表格与文档结构建立记录、来源和工程模型。它并不是任意文件的通用上传解析器。

在持有对应结构资料的环境中，可按以下命令初始化，`original.zip` 为该环境自行准备的资料包：

```powershell
$env:PYTHONPATH = Join-Path $PWD 'backend'
.\.venv\Scripts\python.exe -m icp.ingest .\data\raw\original.zip
```

OCR 校对、图谱抽取及平台索引需要继续执行相关脚本并核对结果；仅上述预处理不等价于历史完整平台验收。原生图谱来源与知识版本须匹配。

## 本地工作台

具备知识包、前端构建与配置后运行：

```powershell
.\scripts\start-local.ps1
```

浏览器打开 `http://127.0.0.1:8000/`。关闭浏览器不停止后端，在启动终端按 `Ctrl+C` 停止。

## 完整平台集成

`deploy/platform-sources.lock.json` 锁定平台源码版本。准备 Dify、RAGFlow、嵌入与重排模型后，通过 `scripts/prepare_platform_sources.py`、`scripts/configure_platforms.py` 生成私有平台配置，并按脚本参数启动各平台。`deploy/dify-tools/` 与 `deploy/native/` 是不包含凭据的模板；应用标识和令牌由部署环境生成。

`scripts/publish.py` 将版本化知识写入 PostgreSQL/Neo4j；`scripts/ragflow_sync.py` 建立检索数据；原生工作流绑定由 `scripts/bootstrap_native_workflows.py` 完成。完整集成依赖平台索引、模型与业务数据准备，不能仅导入模板就视为已经验证。

## 验证

`tests/` 保存测试源码，`eval/` 保存固定评测定义。大部分用例依赖对应业务知识包；没有该包时不应把数据缺失错误解释为模型准确率结果。公开仓库不包含历史完整测试输出。
